Record human triage feedback against the findings of an audited repository and report their current state. Load the skill at .claude/skills/track-findings/SKILL.md and follow its full procedure — $ARGUMENTS names the repository (its https URL) and its audit report, followed by zero or more sources: merge-request/PR/commit URLs, Jira keys, --interactive for a triage session with the person, or --auto to import without walking the review queue (no sources = auto-discover the findings' Jira tickets). Statements go through `traust findings import`: core records what needs no interpretation (the /traust grammar from a maintainer, a commit fix trailer) as the logged-in caller and queues the rest for the person to confirm or reject. Machine reports (triage, validation, verification) record through their own skills.

For human countersign/review, $ARGUMENTS may instead select a core finding UUID, `review-cases`, a private `countersign-queue.md`, or reviewed-answer JSON. Use the same track-findings skill's human review procedure: `traust findings review-cases` reads full cards and integrity-checked evidence; `--output /private/path/countersign-queue.md` creates a new 0600 workbench, never overwrites. Page with the returned cursor and unchanged filters. The verified human edits only its single marked typed JSON answer block, initially empty/deferred; `traust findings apply` accepts that file or a JSON object/nonempty bulk array. Never parse checkboxes, prose, quoted report JSON or DECISION lines as approval. Both confirm and reject require actual canonical judged fields and the person's own rationale; no answer means defer. Core owns identity, proof precedence, independent reviewers and atomic decision/review persistence. Use the shared `traust auth` login or explicitly select `--token-stdin`; never expose credentials or submitted rationale in receipts.
